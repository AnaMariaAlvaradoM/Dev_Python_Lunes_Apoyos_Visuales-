01 · El encargo

Doña Marta no pidió un CRUD

Pidió dejar de perder control sobre inventario, ventas y responsabilidades.

El correo que inicia el proyecto

La tienda “La Cosecha”, en Zipaquirá, trabaja con cuaderno y Excel. A veces vende productos agotados, no puede saber quién hizo cada venta, sus ayudantes pueden cambiar precios, los totales manuales fallan y consultar qué hay o qué se vendió se volvió un caos.

La necesidad real: convertir datos dispersos y acciones inseguras en un sistema confiable.

1Hoy

Diseño, estructura profesional y Categoría completa en memoria.

2Persistencia

PostgreSQL y SQLAlchemy convierten entidades en datos duraderos.

3Seguridad

Usuarios, login, JWT y roles protegen las decisiones del negocio.

4Integración

La venta valida stock, calcula totales y conecta el sistema completo.

✓

Promesa de hoy

Pasaremos del correo a un backend que arranca, se documenta solo y ya puede crear y listar categorías.

¿Por qué el celular de la cajera no debería enviar al backend el total ya calculado?

Para pensar

¿Por qué DetalleVenta debe ser una entidad y no una simple lista dentro de Venta?

Ver respuesta

Resuelve una relación muchos a muchos que además tiene datos propios.

Una venta incluye varios productos y un producto aparece en muchas ventas. La cantidad y el subtotal pertenecen a la unión concreta entre ambos: esa línea es DetalleVenta.

i

Lee el modelo como frases

Un usuario hace ventas; una venta tiene detalles; cada detalle apunta a un producto; cada producto pertenece a una categoría.

10 · Construcción activa

El schema protege el contrato

El cliente envía solo el nombre; el sistema asigna el id y lo incluye en la respuesta.

Compara · 30 segundos

Si el cliente pudiera enviar el id, ¿qué campo estaría controlando sin corresponderle?

Comprobar razonamiento

El identificador pertenece al sistema. Por eso entrada y salida usan modelos distintos: CategoriaCrear recibe el nombre y CategoriaRespuesta añade el id.

01

Haz explícita la regla del nombre

Field concentra una validación observable: entre 2 y 50 caracteres. FastAPI rechazará antes de entrar a nuestra lógica lo que rompa ese contrato.

Fragmentola_cosecha/app/schemas/categoria_schema.py
class CategoriaCrear(BaseModel):
    nombre: str = Field(min_length=2, max_length=50)
Ver categoria_schema.py completoCrear · la_cosecha/app/schemas/categoria_schema.py · Python
Crearla_cosecha/app/schemas/categoria_schema.py
from pydantic import BaseModel, Field


class CategoriaCrear(BaseModel):
    nombre: str = Field(min_length=2, max_length=50)


class CategoriaRespuesta(BaseModel):
    id: int
    nombre: str
Checkpoint

Dos contratos, dos responsabilidades

La entrada acepta nombre; la respuesta garantiza id y nombre.

11 · Construcción activa

El service guarda y decide

Una lista funciona como base de datos temporal; un contador asigna identificadores durante la ejecución.

Predice · 30 segundos

¿Qué debe ocurrir con el contador después de guardar una categoría?

Comprobar razonamiento

Debe aumentar una vez para que la siguiente categoría reciba otro id. global contador_id permite modificar la variable de módulo dentro de la función.

01

Construye una categoría válida

El service recibe un objeto ya validado, crea el diccionario, lo agrega a la colección, avanza el id y devuelve el recurso creado.

Fragmentola_cosecha/app/services/categoria_service.py
def crear_categoria(datos: CategoriaCrear):
    global contador_id
    nueva = {"id": contador_id, "nombre": datos.nombre}
    categorias.append(nueva)
    contador_id += 1
    return nueva

12 · Integración

El router traduce; la app conecta

GET delega el listado, POST recibe datos validados y responde 201. Ninguna lógica de negocio vive aquí.

Detecta · 30 segundos

¿Sería correcto que el router modificara la lista categorias directamente?

Comprobar razonamiento

No. El router traduce HTTP y delega. Modificar datos es responsabilidad del service; mezclarlo dificulta probar y cambiar la persistencia.

Ver categoria_router.py completoCrear · la_cosecha/app/routers/categoria_router.py · Python
Crearla_cosecha/app/routers/categoria_router.py
from fastapi import APIRouter, status
from app.schemas.categoria_schema import CategoriaCrear, CategoriaRespuesta
from app.services import categoria_service

router = APIRouter(prefix="/categorias", tags=["Categorías"])


@router.get("/", response_model=list[CategoriaRespuesta])
def listar():
    return categoria_service.listar_categorias()


@router.post("/", response_model=CategoriaRespuesta, status_code=status.HTTP_201_CREATED)
def crear(datos: CategoriaCrear):
    return categoria_service.crear_categoria(datos)

include_router suma todas las rutas del módulo a la aplicación principal y las incorpora en OpenAPI.

15 · Cierre

Ahora el esqueleto respira

La Cosecha pasó de un correo con problemas a un proyecto organizado, ejecutable y con un primer recurso vivo.

  • Problema resuelto hoy: ya existe una base técnica coherente sobre la cual construir el sistema.
  • Construcción: FastAPI arranca, documenta la API y crea/lista categorías mediante schema, service y router.
  • Cambio real: la necesidad del negocio ya tiene un diseño de entidades, roles y endpoints; no es una lista suelta de tecnologías.
  • Idea 1: cada dolor del cliente se traduce en una decisión técnica.
  • Idea 2: separar responsabilidades permite crecer agregando piezas en vez de reescribir todo.
  • Idea 3: FastAPI y Pydantic convierten tipos y modelos en validación y documentación automáticas.
  • Siguiente necesidad: las categorías desaparecen al reiniciar; la Clase 2 reemplaza la memoria por PostgreSQL y SQLAlchemy.
Última comprobación

Apaga el servidor, vuelve a iniciarlo y lista las categorías. ¿Por qué desaparecieron?

Ver puente a la Clase 2

No hubo un error: la lista vive en RAM y se vacía cuando termina el proceso. Necesitamos persistencia en disco mediante una base de datos real.
