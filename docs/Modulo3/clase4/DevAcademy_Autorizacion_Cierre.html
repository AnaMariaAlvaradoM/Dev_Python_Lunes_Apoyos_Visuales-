02 · Modelo mental

Tres filtros, una sola petición

Cada filtro responde una pregunta distinta y puede detener el flujo.

1Identidad

¿El access token es válido y corresponde a un usuario existente? Si no: 401.

2Rol

¿El usuario pertenece al conjunto permitido para esta operación? Si no: 403.

3Dato o relación

¿Es dueño del curso o del curso padre de la lección? Si no: 403.

Recorrido de una petición protegida
flowchart LR A[Bearer token] --> B{Access válido} B -- no --> X[401] B -- sí --> C[Usuario en BD] C --> D{Rol permitido} D -- no --> Y[403] D -- sí --> E{Dueño directo o heredado} E -- no --> Z[403] E -- sí --> F[Ejecutar operación]
401 · No autenticado

No se pudo demostrar una identidad válida.

403 · No autorizado

La identidad es válida, pero no tiene permiso para esa acción o ese dato.

03 · Autenticación reutilizable

Del token al usuario actual

Una dependencia valida el access token; otras dos agregan la decisión de rol.

Predice · 30 segundos

¿Por qué no conviene revisar el rol dentro de la misma función que obtiene al usuario?

Piensa en un endpoint que solo necesita “cualquier usuario autenticado”.

Comprobar razonamiento

Responsabilidad única: una dependencia identifica; las demás autorizan. Así se combinan según la necesidad de cada endpoint.

01

Extraer y validar identidad

OAuth2PasswordBearer obtiene el token. verificar_token exige tipo access. El sub se convierte a entero de forma segura antes de consultar la base.

from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from sqlalchemy.orm import Session
from app.database import get_db
from app.auth.seguridad import verificar_token
from app.models.usuario import Usuario

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="auth/login")

def obtener_usuario_actual(
    token: str = Depends(oauth2_scheme),
    db: Session = Depends(get_db)
) -> Usuario:
    credenciales_invalidas = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="No se pudo validar el token",
        headers={"WWW-Authenticate": "Bearer"},
    )

    payload = verificar_token(token, tipo_esperado="access")
    if payload is None:
        raise credenciales_invalidas

    try:
        usuario_id = int(payload.get("sub"))
    except (TypeError, ValueError):
        raise credenciales_invalidas

    usuario = db.query(Usuario).filter(Usuario.id == usuario_id).first()
    if usuario is None:
        raise credenciales_invalidas

    return usuario

def requerir_instructor(
    usuario: Usuario = Depends(obtener_usuario_actual)
) -> Usuario:
    if usuario.rol not in ("instructor", "admin"):
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Requiere permisos de instructor"
        )
    return usuario

def requerir_admin(
    usuario: Usuario = Depends(obtener_usuario_actual)
) -> Usuario:
    if usuario.rol != "admin":
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Requiere permisos de administrador"
        )
    return usuario
Checkpoint

Señal de éxito

Sin token, un endpoint protegido responde 401. Con un access token válido, recibe el objeto Usuario.

@router.post("/refresh")
def refrescar(datos: TokenRefresh, db: Session = Depends(get_db)):
    payload = verificar_token(
        datos.refresh_token,
        tipo_esperado="refresh"
    )

    if payload is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Refresh token inválido o expirado",
            headers={"WWW-Authenticate": "Bearer"},
        )

    try:
        usuario_id = int(payload.get("sub"))
    except (TypeError, ValueError):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Refresh token inválido o expirado",
            headers={"WWW-Authenticate": "Bearer"},
        )

    usuario = db.query(Usuario).filter(Usuario.id == usuario_id).first()
    if usuario is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Usuario no encontrado",
            headers={"WWW-Authenticate": "Bearer"},
        )

    nuevo_access = crear_access_token({"sub": str(usuario.id)})
    return {"access_token": nuevo_access, "token_type": "bearer"}

from sqlalchemy.orm import Session
from fastapi import HTTPException, status
from app.models.curso import Curso

def crear_curso(
    db: Session,
    titulo: str,
    descripcion: str,
    instructor_id: int
) -> Curso:
    nuevo_curso = Curso(
        titulo=titulo,
        descripcion=descripcion,
        instructor_id=instructor_id
    )
    db.add(nuevo_curso)
    db.commit()
    db.refresh(nuevo_curso)
    return nuevo_curso

def listar_cursos(db: Session):
    return db.query(Curso).all()

def obtener_curso(db: Session, curso_id: int) -> Curso:
    curso = db.query(Curso).filter(Curso.id == curso_id).first()
    if not curso:
        raise HTTPException(status_code=404, detail="Curso no encontrado")
    return curso

def actualizar_curso(
    db: Session,
    curso_id: int,
    titulo: str,
    descripcion: str,
    usuario_id: int
) -> Curso:
    curso = obtener_curso(db, curso_id)

    if curso.instructor_id != usuario_id:
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Este curso no es tuyo"
        )

    curso.titulo = titulo
    curso.descripcion = descripcion
    db.commit()
    db.refresh(curso)
    return curso

from sqlalchemy.orm import Session
from fastapi import HTTPException
from app.models.inscripcion import Inscripcion
from app.services.curso_service import obtener_curso

def inscribir(
    db: Session,
    estudiante_id: int,
    curso_id: int
) -> Inscripcion:
    obtener_curso(db, curso_id)

    existente = db.query(Inscripcion).filter(
        Inscripcion.estudiante_id == estudiante_id,
        Inscripcion.curso_id == curso_id
    ).first()
    if existente:
        raise HTTPException(
            status_code=400,
            detail="Ya estás inscrito en este curso"
        )

    nueva = Inscripcion(
        estudiante_id=estudiante_id,
        curso_id=curso_id,
        estado="activa"
    )
    db.add(nueva)
    db.commit()
    db.refresh(nueva)
    return nueva

def listar_mis_inscripciones(db: Session, estudiante_id: int):
    return db.query(Inscripcion).filter(
        Inscripcion.estudiante_id == estudiante_id
    ).all()

13 · Verificación y diagnóstico

Leer el resultado antes de cambiar código

Cada señal apunta a una capa distinta del flujo.

i

Swagger con OAuth2PasswordBearer

En /docs, abre Authorize y autentícate con username (el correo) y password. Swagger solicita y guarda el access token. La opción de pegar un Bearer manual corresponde a un esquema HTTPBearer distinto.

“Not authenticated” · 401

Falta el Bearer, expiró el access token o se envió un token de tipo incorrecto.

403 al crear curso

El token pertenece a un estudiante. Cambia al usuario instructor esperado.

403 al crear lección

El curso no pertenece al instructor autenticado. Revisa el curso_id.

ImportError al arrancar

Un módulo o nombre no coincide. Revisa rutas, archivos e imports.

Refresh responde 401

Se envió un access token o el refresh expiró. Cada token tiene su endpoint.

200 donde esperabas 403

Probablemente probaste con el dueño real. Confirma la identidad del token.

!

Dos límites que no debemos ocultar

El admin no tiene bypass de propiedad en la implementación actual. Además, listar lecciones no valida inscripción. Son decisiones pendientes, no comportamientos ya entregados.

La API ya toma decisiones con identidad

El proyecto pasó de reconocer usuarios a proteger acciones y datos con reglas observables.

  • Problema resuelto: una identidad autenticada ya no equivale a permiso ilimitado.
  • Construcción: dependencia de usuario actual, roles, refresh, servicios, routers e integración.
  • Idea 1: 401 significa identidad no demostrada; 403 significa identidad sin permiso.
  • Idea 2: el rol habilita una categoría de acción; la propiedad decide sobre el dato concreto.
  • Idea 3: un permiso puede heredarse a través de una relación, como lección → curso → dueño.
  • Siguiente necesidad: aplicar el control de lectura por inscripción y decidir si el admin tendrá bypass global.
