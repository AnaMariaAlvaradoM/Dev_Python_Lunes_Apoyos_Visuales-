01
Punto de partida

Una receta no cabe en una columna

El problema no es guardar texto: es conservar relaciones que el sistema pueda consultar, validar y ejecutar.

Decisión de negocio

¿Por qué no guardar en Tratamiento una columna “insumos” con una lista como “1 vial, 2 guantes”?

Lista dentro de una columna

  • Convierte la receta en texto muerto.
  • No permite consultar el stock por insumo.
  • No permite descontar cantidades con integridad.

Relación mediante filas

  • Cada insumo conserva su identidad.
  • La cantidad pertenece a la combinación.
  • La base puede consultar y operar la receta.
Caso Patitas Vet

El proyecto continúa, no empieza de cero

Ya existen Dueño, Mascota y Veterinario con sus CRUD, además de la relación Dueño → Mascota. Esta clase agrega Cita, Insumo, Tratamiento, la receta N:M y el descuento transaccional.

02
Modelo mental y arquitectura

Del negocio a relaciones ejecutables

Cada llave foránea expresa una decisión del negocio; la tabla intermedia convierte la receta en datos operables.

N:M

Definición técnica

Ambos lados pueden relacionarse con muchos registros del otro lado, por lo que necesitan una tabla intermedia.

Explicación sencilla

Una receta con ingredientes

Un tratamiento usa varios insumos y el mismo insumo participa en varios tratamientos.

Aplicación profesional

Dato de la relación

“Dos guantes” no pertenece al guante ni a la vacuna: pertenece a esa combinación concreta.

Cuatro capas

Modelo, schema, service y router separan persistencia, contrato, reglas y HTTP.

Integridad

Las FK y las validaciones evitan citas o recetas con referencias inexistentes.

Transacción

Todos los descuentos se confirman juntos o ninguno altera el inventario.

Criterio técnico

La IA puede proponer código; tú debes validar el modelo

Antes de aceptar una solución, comprueba que la cantidad esté en la tabla intermedia, que las FK apunten a tablas reales y que el descuento no pueda quedar a medias.

03
Checkpoints 01–05

Cita: dos relaciones en una entidad

Una cita registra qué mascota se atendió, quién la atendió, cuándo ocurrió y cuál fue el motivo.

Checkpoint 01 · Crear

Modelo de Cita

Qué construirás: la tabla citas. Por qué: el negocio necesita conectar Mascota y Veterinario. Qué aprenderás: una entidad puede tener dos llaves foráneas.

CREARapp/models/cita_model.py
from sqlalchemy import Column, Integer, String, Date, ForeignKey
from sqlalchemy.orm import relationship
from app.config.database import Base


class Cita(Base):
    __tablename__ = "citas"

    id = Column(Integer, primary_key=True, index=True)
    fecha = Column(Date, nullable=False)
    motivo = Column(String, nullable=False)

    mascota_id = Column(Integer, ForeignKey("mascotas.id"), nullable=False)
    veterinario_id = Column(Integer, ForeignKey("veterinarios.id"), nullable=False)

    mascota = relationship("Mascota")
    veterinario = relationship("Veterinario")
Cómo se conecta

Date almacena la fecha; las dos FK hacen obligatoria una mascota y un veterinario reales. Los dos relationship permiten navegar a los objetos completos desde Python.

Checkpoint 02 · Crear

Contrato de entrada y salida

Qué construirás: los schemas de Cita. Por qué: FastAPI necesita validar fechas e ids. Qué aprenderás: separar el payload de creación de la respuesta persistida.

Pydantic exige una fecha con formato válido y números enteros para las relaciones. from_attributes permite convertir el objeto de SQLAlchemy en la respuesta HTTP.

Checkpoint 03 · Crear

Service con doble validación

Qué construirás: la lógica de creación y consulta. Por qué: una FK válida en intención debe apuntar a un registro existente. Qué aprenderás: validar relaciones antes de guardar.

CREARapp/services/cita_service.py
from sqlalchemy.orm import Session
from fastapi import HTTPException
from app.models.cita_model import Cita
from app.models.mascota_model import Mascota
from app.models.veterinario_model import Veterinario
from app.schemas.cita_schemas import CitaCreate


def crear_cita(db: Session, datos: CitaCreate):
    mascota = db.query(Mascota).filter(Mascota.id == datos.mascota_id).first()
    if mascota is None:
        raise HTTPException(status_code=404, detail="La mascota indicada no existe")

    veterinario = db.query(Veterinario).filter(Veterinario.id == datos.veterinario_id).first()
    if veterinario is None:
        raise HTTPException(status_code=404, detail="El veterinario indicado no existe")

    nueva = Cita(
        fecha=datos.fecha,
        motivo=datos.motivo,
        mascota_id=datos.mascota_id,
        veterinario_id=datos.veterinario_id,
    )
    db.add(nueva)
    db.commit()
    db.refresh(nueva)
    return nueva


def listar_citas(db: Session):
    return db.query(Cita).all()


def obtener_cita(db: Session, cita_id: int):
    return db.query(Cita).filter(Cita.id == cita_id).first()
Cómo se conecta

Primero se consultan Mascota y Veterinario. Cualquier ausencia corta la operación con 404; solo después se crea la cita y se confirma con commit().

Checkpoint 04 · Crear

Endpoints de Cita

Qué construirás: las rutas para crear, listar y obtener. Por qué: el service necesita una interfaz HTTP. Qué aprenderás: delegar la regla de negocio sin duplicarla en el router.

CREARapp/routers/cita_router.py
from fastapi import APIRouter, Depends, HTTPException
from sqlalchemy.orm import Session
from app.config.database import get_db
from app.schemas.cita_schemas import CitaCreate, CitaRespuesta
from app.services import cita_service

router = APIRouter(tags=["Citas"])


@router.post("/citas", response_model=CitaRespuesta)
def crear(datos: CitaCreate, db: Session = Depends(get_db)):
    return cita_service.crear_cita(db, datos)


@router.get("/citas", response_model=list[CitaRespuesta])
def listar(db: Session = Depends(get_db)):
    return cita_service.listar_citas(db)


@router.get("/citas/{cita_id}", response_model=CitaRespuesta)
def obtener(cita_id: int, db: Session = Depends(get_db)):
    cita = cita_service.obtener_cita(db, cita_id)
    if cita is None:
        raise HTTPException(status_code=404, detail="Cita no encontrada")
    return cita
Cómo se conecta

El router inyecta la sesión, aplica los schemas y delega al service. El único 404 local corresponde a consultar una cita que no existe.

Checkpoint 05 · Editar

Registrar Cita en la aplicación

En app/main.py, importa cita_model para que create_all conozca la tabla; importa cita_router y añade app.include_router(cita_router.router). La guía de origen no aporta un bloque consolidado de main.py, por lo que este cambio se conserva como instrucción y no se inventa código.

Errores que debes saber leer

Las relaciones no existen

404 “La mascota indicada no existe” o 404 “El veterinario indicado no existe” significa que uno de los ids del payload no corresponde a un registro real. 404 “Cita no encontrada” significa que el id consultado no existe.

Checkpoint 07 · Crear

Checkpoints 15–19

La receta: N:M con cantidad

Cada fila de la tabla intermedia afirma: “este tratamiento usa esta cantidad de este insumo”.

Checkpoint 15 · Crear

Modelo de la tabla intermedia

Qué construirás: la entidad de receta. Por qué: debe guardar dos FK y el atributo cantidad. Qué aprenderás: modelar una relación N:M con datos propios.

CREARapp/models/tratamiento_insumo_model.py
from sqlalchemy import Column, Integer, ForeignKey
from sqlalchemy.orm import relationship
from app.config.database import Base


class TratamientoInsumo(Base):

    id = Column(Integer, primary_key=True, index=True)

Service para armar y consultar la receta

Qué construirás: la creación de líneas y su consulta. Por qué: ambos extremos deben existir. Qué aprenderás: validar y persistir una relación.

CREARapp/services/tratamiento_insumo_service.py
from sqlalchemy.orm import Session
from fastapi import HTTPException
from app.models.tratamiento_insumo_model import TratamientoInsumo
from app.models.tratamiento_model import Tratamiento
from app.models.insumo_model import Insumo
from app.schemas.tratamiento_insumo_schemas import RecetaItemCreate


def agregar_insumo_a_receta(db: Session, tratamiento_id: int, datos: RecetaItemCreate):
    tratamiento = db.query(Tratamiento).filter(Tratamiento.id == tratamiento_id).first()
    if tratamiento is None:
        raise HTTPException(status_code=404, detail="El tratamiento no existe")

    insumo = db.query(Insumo).filter(Insumo.id == datos.insumo_id).first()
    if insumo is None:
        raise HTTPException(status_code=404, detail="El insumo no existe")

    linea = TratamientoInsumo(
        tratamiento_id=tratamiento_id,
        insumo_id=datos.insumo_id,
        cantidad=datos.cantidad,
    )
    db.add(linea)
    db.commit()
    db.refresh(linea)
    return linea


def ver_receta(db: Session, tratamiento_id: int):
    return db.query(TratamientoInsumo).filter(
        TratamientoInsumo.tratamiento_id == tratamiento_id
    ).all()
Cómo se conecta

El service rechaza con 404 cualquier extremo inexistente. Una línea válida se guarda con tratamiento, insumo y cantidad; ver_receta devuelve todas las líneas de un tratamiento.

06
Checkpoints 20–22

Descontar stock con una transacción

Primero se verifica la receta completa; solo después se modifica el inventario y se confirma todo junto.

Qué es

Transacción

Un conjunto de operaciones que se ejecutan todas o ninguna.

Por qué existe

Evita estados parciales

No puede descontarse el vial si después se descubre que faltan guantes.

Aplicación real

Transferencia bancaria

Restar de una cuenta y sumar a otra debe ocurrir completo o revertirse.

1. Buscar receta

Traer insumos y cantidades del tratamiento.

2. Verificar todo

Comparar cada cantidad con el stock actual.

3. Decidir

Si uno falla, cancelar sin tocar el inventario.

4. Confirmar

Si todos alcanzan, descontar y hacer un solo commit.

Checkpoint 20 · Crear

Service de aplicación

Qué construirás: la función central del taller. Por qué: ejecutar una receta no puede corromper el stock. Qué aprenderás: separar verificación, modificación y confirmación.

CREARapp/services/aplicacion_service.py
from sqlalchemy.orm import Session
from fastapi import HTTPException
from app.models.tratamiento_model import Tratamiento
from app.models.tratamiento_insumo_model import TratamientoInsumo
from app.models.insumo_model import Insumo


def aplicar_tratamiento(db: Session, tratamiento_id: int):
    tratamiento = db.query(Tratamiento).filter(Tratamiento.id == tratamiento_id).first()
    if tratamiento is None:
        raise HTTPException(status_code=404, detail="El tratamiento no existe")

    receta = db.query(TratamientoInsumo).filter(
        TratamientoInsumo.tratamiento_id == tratamiento_id
    ).all()

    if not receta:
        raise HTTPException(status_code=400, detail="El tratamiento no tiene receta definida")

    # PASO 1: verificar que haya stock de TODOS antes de tocar nada
    for linea in receta:
        insumo = db.query(Insumo).filter(Insumo.id == linea.insumo_id).first()
        if insumo.stock < linea.cantidad:
            raise HTTPException(
                status_code=409,
                detail=f"Stock insuficiente de {insumo.nombre}: hay {insumo.stock}, se necesitan {linea.cantidad}",
            )

    # PASO 2: si llegamos aquí, TODO alcanza. Ahora sí descontamos.
    for linea in receta:
        insumo = db.query(Insumo).filter(Insumo.id == linea.insumo_id).first()
        insumo.stock = insumo.stock - linea.cantidad

    db.commit()
    return {"mensaje": f"Tratamiento '{tratamiento.nombre}' aplicado. Inventario actualizado."}
Cómo funciona

El primer recorrido solo lee. Un raise 409 termina la función antes de cualquier descuento. El segundo recorrido se ejecuta únicamente cuando todos los insumos alcanzan.

El commit() único confirma todos los cambios juntos. Aquí no aparece un rollback() explícito porque la verificación sucede antes de modificar: si falla, nunca hay cambios pendientes que confirmar.

Decisión de seguridad

¿Por qué recorrer la receta dos veces en vez de verificar y descontar insumo por insumo?

Respuesta técnica

Medir dos veces evita devolver cambios

Si el tercer insumo falla después de descontar los dos primeros, el inventario queda parcial o exige revertirlo. Verificar todo primero garantiza que la modificación comienza solo cuando la receta completa puede cumplirse.

Consulta 1: mascotas con su dueño

from sqlalchemy.orm import Session
from app.models.mascota_model import Mascota
from app.models.dueno_model import Dueno


def mascotas_con_dueno(db: Session):

Checkpoint 24 · Añadir

Consulta 2: citas por veterinario

Qué construirás: una agregación. Por qué: gestión necesita totales, no filas crudas. Qué aprenderás: combinar count, JOIN y group_by.

AÑADIRapp/services/consultas_service.py
from sqlalchemy import func
from app.models.cita_model import Cita
from app.models.veterinario_model import Veterinario


def citas_por_veterinario(db: Session):
    resultado = (
        db.query(Veterinario.nombre, func.count(Cita.id).label("total_citas"))
        .join(Cita, Cita.veterinario_id == Veterinario.id)
        .group_by(Veterinario.nombre)
        .all()
    )
    return [{"veterinario": fila.nombre, "total_citas": fila.total_citas} for fila in resultado]
Dónde añadir

Añade estos imports junto a los existentes y la función después de mascotas_con_dueno. group_by forma un grupo por veterinario y count cuenta las citas de cada grupo.

Diagnóstico y criterio

Lee el error antes de cambiar el código

Un mensaje útil comunica si falta un recurso, si el payload es inválido o si el estado actual impide la operación.

404 · Recurso inexistente

Citas y catálogos

“La mascota indicada no existe”, “El veterinario indicado no existe”, “Cita no encontrada”, “Insumo no encontrado” o “Tratamiento no encontrado” indican que el id solicitado no corresponde a un registro real.

404 · Receta y aplicación

Extremos inexistentes

“El tratamiento no existe” o “El insumo no existe” significa que se intentó crear o ejecutar una relación con un extremo ausente.

422 · Validación

Payload fuera de contrato

Ocurre si un nombre queda fuera de 2–50 caracteres, el stock es negativo, el precio no es mayor que cero o la cantidad de receta es cero o negativa.

400 · Petición inválida

Tratamiento sin receta

El tratamiento existe, pero no tiene líneas de receta. Debes agregar sus insumos antes de aplicarlo.

409 · Conflicto

Stock insuficiente

El recurso existe y la petición está bien formada, pero el inventario actual no permite ejecutar la receta completa.

Referencia rota

insumo is None

La receta apunta a un insumo eliminado. Verifica que sus ids correspondan a registros existentes.

Persistencia

El stock no baja

Revisa que aplicar_tratamiento llegue al commit() y que consultes el inventario después de aplicar.

Datos

El JOIN devuelve vacío

No necesariamente es un error de sintaxis: puede no haber datos relacionados. Crea citas o relaciones antes de consultar.

Import

func no está definido

Falta from sqlalchemy import func en consultas_service.py.

Registro de modelo

No aparece tratamiento_insumo

Importa el modelo en main.py antes de ejecutar create_all.
